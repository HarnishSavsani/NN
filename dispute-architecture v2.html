C1 — System Context
Who uses the system and what does it touch?
Four human actors, five external data sources, and an on-premise GPU inference cluster — all within the financial institution's network perimeter. Cardholder PAN, transaction data, and dispute evidence never leave the institution's boundary. Cloud LLM providers are explicitly excluded as a primary path; inference runs on a locally hosted SLM (Phi-4 / Mistral-7B via vLLM) to satisfy PCI-DSS 4.0, GDPR Article 28, RBI 2018, SAMA, CBUAE, and APRA CPS 234 data residency requirements.

Regulatory rationale: PCI-DSS 4.0 Req 4.2 prohibits transmitting PAN or SAD to untrusted third parties. GDPR Art. 28 requires a signed DPA before cardholder PII reaches any processor — major LLM vendors do not qualify. RBI 2018 mandates India-only storage for payment system data. SAMA / CBUAE require in-country residency for Saudi / UAE payment data. APRA CPS 234 makes external AI outsourcing a board-level risk item. On-prem SLM eliminates all of these blockers before the ROI conversation begins.
C2 — Container Diagram
Microservices, databases, event bus, and on-prem inference cluster
Eleven microservices communicating over a Redis event bus, three SQLite databases (dispute, workflow, audit-only), a Channel Gateway normalising five inbound intake channels (Mobile App 42%, Email Parser 34%, Merchant Portal 12%, Card Network 4%, IVR/Branch 8%) and routing all case-creation requests to the Dispute Manager, an API gateway as the single human-facing entry point, and a two-tier on-prem SLM cluster (vLLM primary + Ollama fallback) exposing an OpenAI-compatible REST API internally. The Presidio PII Scrubber is a mandatory checkpoint before every inference call — it strips and tokenises sensitive fields and writes an audit log entry per scrub. The Model Registry tracks adapter versions and GPU endpoints. All inference traffic stays inside the institution's perimeter.

C3 — Component Diagram · AI Inference Engine
Inside the AI Inference Engine microservice
Thirteen components implement a fully on-premise, regulation-compliant inference pipeline. The Presidio PII Scrubber (mandatory security checkpoint) strips and tokenises sensitive fields before every model call — no prompt ever reaches the SLM or cloud fallback without passing through it. LiteLLM routes to the on-prem vLLM server (Phi-4 14B, QLoRA-adapted) as primary, falls back to on-prem Ollama (Mistral-7B) on degraded state, and only reaches a cloud endpoint as a last resort — with pre-scrubbed input and explicit audit logging. The Model Registry tracks which adapter version served each inference. Bayesian confidence gates STP vs. human routing; deepDiff material-change detection prevents redundant re-scoring.

On-Prem SLM · Architecture
Regulation-compliant inference — inside the institution's perimeter

The QLoRA adapter is the only artefact trained outside the cluster and is deployed alongside the base weights at launch time.

On-Prem SLM · Fine-Tuning Strategy
QLoRA domain adaptation — dispute intelligence from synthetic data
A QLoRA fine-tune converts a general-purpose base SLM into a dispute-classification specialist in approximately 4 hours on a single A100, using synthetic training data generated from the scenario library. The adapter is the only training artefact; base weights stay untouched and on-prem. As real anonymised cases accumulate inside the institution, the adapter is updated in subsequent training runs entirely within the perimeter.

Data strategy: Synthetic data bootstraps the first adapter — no labelled real cases needed at launch. The model learns the output schema (structured JSON: recommendation, confidence, reasoning, evidence_weight_map), the Reg-E / Visa / MC domain vocabulary, and the jurisdiction-specific rules. As real anonymised cases accumulate inside the perimeter they update the adapter in subsequent runs. The training pipeline itself runs on-prem; the only external dependency is the one-time base weight download at deployment.
C4 — Code / Domain Model

Seven domain classes form the backbone of the system. EvidenceItem is versioned — materialness changes create a new EvidenceVersion rather than mutating the original. AuditEvent is append-only and hash-chained. All human decisions are captured as ApprovalRequest records with mandatory rationale.

Sequence Diagram · SC-03
AI Hypothesis Generation — On-Prem SLM · Low Confidence Path
Detailed view of the on-prem inference pipeline. PII Scrubber runs before every model call. LiteLLM routes to the vLLM server (Phi-4 14B QLoRA-adapted) as primary; falls back to Ollama (Mistral-7B) if vLLM is unhealthy. When Bayesian confidence falls below 0.75 the case is routed to the analyst queue; below 0.50 it escalates directly to the manager queue.

Partial Failure Recovery — Timeout, Retry, and Checkpoint Restoration
A service crash occurs mid-workflow after repeated timeouts. On restart, the Recovery Orchestrator loads the last valid checkpoint from SQLite and replays events from that point. Sequence Diagram · SC-07
